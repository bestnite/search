给 DeepSeek Harness 用的多后端网页搜索：24 家搜索服务，逐个开关，每个都明确选定接入模式、标明费用档。

## 安装

```sh
dsh plugin add @nite07/dsh-search
dsh --profile web   # 或者用你自己的方式重启 dsh web
```

也可以在 **设置 → 插件 → 添加插件** 里安装。

装完把它设为搜索来源：打开 **设置 → 网页搜索**，如果页面提示当前不是本插件，点「**设为网页搜索来源**」。

## 第一次搜索

1. 打开 **设置 → 网页搜索**
2. 在「搜索」页签里挑一个不需要账号的启用：Keenable、AnySearch、Exa、Parallel、You.com、DuckDuckGo 或 Reddit
3. 看一眼那一行的费用说明，点「保存设置」
4. 让 agent 搜点东西

所有后端默认关闭，不保存就一个请求都不会发出。想绕开 agent 单独验某一家通不通，用「试搜与诊断」页签：它明确发一次真实请求，把结果和失败原因原样显示出来。

## 加 Key

`key` 或 `session` 模式的后端需要凭证。把 Key 填到那一行的凭证输入框再保存，插件会把它存进 DSH 的凭据库，名字在代码里固定，所以配置文件没办法把某次查询指向别的密钥。配置文件本身不保存 Key。

## 后端与费用

列表按**每家最便宜的用法**分组，所以有完全免费路径的永远排在最前面。每行用 chip 标出**所有**模式各自的费用档，当前选中的那个高亮。

| 分组 | 有哪些 | 说明 |
| --- | --- | --- |
| **有完全免费的用法** | Keenable、AnySearch、Exa、Parallel、You.com、DuckDuckGo、Reddit | 不用注册、不用 Key，开箱可用 |
| **自带账号** | X | 用你自己 X 网页端的 cookie，不花钱，但 X 改动页面里内嵌的接口时会失效 |
| **自托管** | SearXNG、open-websearch、小红书（Xiaohongshu） | 自己跑服务，额度由你自己定；小红书走的是你自己托管的浏览器 |
| **免费额度** | Linkup、Tavily、Brave、知乎（网页/站内）、百度、豆包 | 注册拿 Key，额度内免费 |
| **试用额度** | Serpex | 一次性试用额度，用完转付费 |
| **付费** | Mojeek、Anthropic、OpenAI、DeepSeek、腾讯 WSA | 按量收费，开之前先看单价 |

- 默认**全部关闭**，一个都不会自动启用
- 各家的具体额度、单价、来源链接和核实日期见 [docs/BACKENDS.md](docs/BACKENDS.md)

## 小红书

小红书只认自己的页面运行时，没有能直接调的 HTTP 接口，所以它走你自己托管的浏览器：不按次计费，成本就是那台跑浏览器的机器。

1. 按 [packages/core/image](../core/image/README.zh.md) 起浏览器容器，启动日志会打印端点和令牌
2. 打开 `http://<host>:6080/vnc.html`，在那扇已经开着的窗口里登录小红书。容器每分钟把登录态写进磁盘
3. 打开 **设置 → 网页搜索 → 浏览器**，填共享端点（`ws://<host>:3000/ws`）、可选的会话文件、读取超时与同站点并发读取数，再把启动日志里的令牌填进「端点令牌」。这个 Tab 会列出所有依赖它的已启用功能
4. 在 **搜索** Tab 把小红书后端的模式设为 browser，启用并保存。保存前会检查端点与令牌；被拒绝时到「浏览器」Tab 点 **检查连接** 看具体原因

令牌保护的是浏览器端点，不是网站账号，所以它按浏览器存一份，不按后端存。共享端点优先于后端自己的端点，后端里那个只在共享端点留空时兜底。会话文件必须和容器写的是同一个文件，否则每次读回来都是未登录。插件本身没法登录，登录永远留在那个浏览器的主人手里。

同站点并发读取数限制的是同一个站点上同时跑几个浏览器读取，这和「搜索行为」里的全局并行数量不是一回事：后者限制的是一次搜索同时问几家后端。遇到 429 限流后，本次浏览器会话会保守降到 1。

## 工具

- `web_search` — 上面说的多后端搜索。
- `web_search_plus` — 按本次调用指定搜索策略：`mode`（单后端/并行）、`backends`（从已启用里挑子集）、`allBackends` + `exclude`（全用但排掉几家）、`compact`（只回标题和链接，省结果 token）和 `maxResults`。只影响这一次调用，不改配置；没启用的后端会被明确告知而不是被悄悄忽略，实际用了哪些也会回显。可在设置里关闭。
- `x_thread` — 读一条 X 推文及其回复；需要 X 后端处于会话模式，深度、回复条数和字符预算都有上限。
- `xiaohongshu_note` — 读一篇小红书笔记：正文、作者、赞藏评转、标签、配图，需要的话再读一层评论。吃分享链接（里面带着读取要用的 token）或本次会话里搜到的笔记 id；需要小红书后端处于 browser 模式且共享浏览器端点已配置。
- `reddit_thread` — 读某个 Reddit 帖子的完整评论树；按深度、评论条数和字符预算截断。
- `backend_status` — 一眼看清现在开了什么：启用了哪些后端、各自的模式、费用档、凭证是否就位（只报有没有，不回值）、今天调了几次、上次成功还是失败以及失败原因，另外告诉你插件是不是当前的搜索来源。传一个后端 id 可以看它的全部模式、额度和可选项。只读，不会启用任何东西，也不花钱。
- `search_manage` — 从 agent 侧查看或修改本插件自己的设置，包括共享浏览器令牌（`scope: browser`）而不只是某个后端的凭证。

- `web_extract` — 抓取**单个**页面：`url` 加必填的 `format`（`markdown` 用来读，`html` 用来看结构）。
  路由顺序、服务商选择、凭证与回退规则都来自保存的配置，不能由调用参数覆盖；返回的页面内容不可信。
  **默认关闭**：在「页面抓取」Tab 打开「允许使用 web_extract」才会注册该工具，关闭时完全不注册，
  避免已经有原生抓取工具的 agent 多拿一个重复工具。

## 页面抓取

同一设置页在「搜索」旁边有「页面抓取」Tab，编辑的是同一份草稿：

- **路由**：HTTP、共享浏览器、一个服务商，各有独立开关、超时、顺序（↑/↓ 按钮，键盘可达）与回退规则。
  规则之间是「或」，规则内条件是「且」，条件结果为真/假/不可用；字段缺失不当作空字符串。预设只是普通
  可编辑规则：一个状态码规则，一个启发式的验证页规则。
- **服务商**：只显示具备抓取能力的服务商（本版本是 Exa 与 Parallel），列出可返回的格式，并单独保存
  抓取的接入模式、传输方式、端点、超时与选项。服务商卡片默认收起，只有你自己点击才会展开；在上方下拉里
  选服务商不会顺带展开卡片，选中状态由卡片上的标签表示。两家各有无 Key 的 MCP 模式与有 Key 的 REST 模式：
  无 Key 模式经过实测，有 Key 模式只有文档核实（没有付费调用），卡片上会标明；有 Key 抓取复用该服务商唯一
  的那份搜索密钥，没有密钥时不发请求、记为 authentication 失败，回退规则可以命中它并交给下一条路由。
  两者都只返回原生 Markdown；请求 HTML 时会在不发请求的情况下跳过，由下一条启用的路由提供页面。
- **安全与上限**：总期限、重定向上限、采集与输出上限、规则扫描宽度，以及公网/私有网络策略。浏览器/
  服务商路由由远端自行解析目标地址，因此打开这条路由本身就是「委托抓取」的决定；没有第二个开关，这类
  路由的每条结果都会写明这个信任边界。
- **测试**：URL、必选格式，针对**已保存**配置手动执行一次；会访问网络，服务商可能计费，渲染或保存时
  不会自动运行。

测试前会先显示就绪问题：没有启用路由、浏览器路由没有端点、服务商路由没有选择服务商，或缺少服务商凭证。

## 设置页结构

整页只编辑一份草稿。切换 Tab 不会保存、不会丢弃修改，也不会把值在两种操作之间搬来搬去。

| Tab | 负责什么 |
| --- | --- |
| **搜索行为** | 查询形态、安全搜索、语言与地区、agent 工具开关 |
| **可靠性** | 重试、熔断、缓存与诊断保留量 |
| **测试与诊断** | 针对已保存设置手动测试单个后端、最近结果、导入导出 |
| **搜索** | 后端目录：接入模式、费用标签、搜索端点与凭证 |
| **浏览器** | 共享 Playwright 端点、端点令牌、会话文件、单站点并发上限，以及所有依赖它的已启用搜索/抓取功能 |
| **页面抓取** | 路由、回退规则、抓取服务商（固定下拉选择，包含「不选」）、抓取操作设置，以及只属于抓取的浏览器上下文/等待/选择器选项 |

搜索与页面抓取使用同一种服务商卡片。一个后端的凭证只有一份，绑在同一条记录上：输入框只有一处，在「搜索」页的
卡片里，只要搜索或抓取任一模式需要 Key 就会渲染（所以搜索保持匿名、抓取用有 Key 模式也能录入）；「页面抓取」
页只显示已配置/未配置并直接跳到这个输入框，同一把 key 不会要求输入两次。搜索的上限不会约束页面抓取：
抓取操作保留自己的接入模式、传输方式、端点、超时与选项，卡片上会写明，也会标出哪些接入模式是实测的、
哪些只是依据文档实现的。

## 保存与浏览器校验

保存结果不再显示在长页面顶部，而是浮在设置面板之上的卡片：成功会几秒后自动消失，且不会抢走键盘焦点；
被拒绝的卡片一直保留到手动关闭，每条原因都能直接跳到对应字段；保存进行中是另一张中性卡片，不会被当成
被拒绝。读回的配置与服务端报告的版本一致才算保存成功，配置按「值」比较而不是按 JSON 文本比较，
所以键的顺序不同（旧版本保存的行会把新块排在末尾）不会被当成差异。

**保存设置**先校验再写入，结果明确区分：

- **校验被拒绝**：不写入任何内容。草稿保留全部修改，页面列出已本地化的原因，点击即可切到对应 Tab、
  展开服务商卡片或回退规则，并把焦点放到真正的控件上。路由问题按路由类型（HTTP、浏览器、服务商）显示，
  而不是数组下标，所以调换顺序后仍然可读。
- **版本冲突**：另一个窗口先保存了。版本会在编辑器的文件锁内、按实际当前生效的条目配置（再做 migration 与
  schema 默认填充）再次核对。继承层不会再合并回来：profile patch 的值是整体替换，合并会复活已被替换的旧值。
  因此验证期间落地的保存不会被覆盖。页面会重新读取最新版本并保留你的草稿，不把它报成非法值。
- **已取消**：请求或插件生命周期在验证期间被取消。写入前就会停下，草稿不变。
- **确定的写入失败**：服务端报告写入失败；页面会先回读保存状态再下结论。回读成功且与草稿不同，会连同
  服务端原因一起显示并保留草稿；回读失败则显示「结果未知」，不会声称没有写入。
- **无法确认的响应**：只有传输失败且回读后发现保存状态不一致时才这样报；本页发出的保存请求从不自动重放。

当已启用的搜索后端走浏览器（小红书），或抓取的浏览器路由开启时，服务端会在写入前验证实际生效的端点：
读取已保存的令牌，按不同的「端点 + 令牌」组合各连接一次，创建并关闭一个隔离上下文，然后断开。整个过程
（读取令牌、连接、上下文与清理）限制在约 5 秒内，不导航、不发站点或业务请求，也不会关闭其他客户端在用的
远端浏览器。连接成功只说明端点与令牌可用，**不代表**站点已登录。

搜索路径优先使用共享端点，仅当共享端点为空时才用后端自己的端点；页面抓取的浏览器路由只使用共享端点。
分组校验遵循同样的规则，所以搜索后端的自有端点不会让抓取路由看起来已通过验证。

所有依赖浏览器的功能都关闭时，浏览器设置可以在离线状态直接保存，不会发起探测。可以先关闭依赖、保存、
再修端点或令牌，最后重新保存启用状态。

**浏览器** Tab 可以针对草稿中的端点手动执行同样的有时限检查，且在保存前就能做。检查不接受凭证参数，
始终使用已保存的令牌；agent 侧只能复检已保存的端点。端点或令牌一改，页面上的检查结果就标记为过期，而每次
保存都会在服务端重新检查实际生效的端点。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 搜不出东西 | 后端在你保存之前都是关闭的。去「搜索」页签启用一家再保存。 |
| 小红书报未登录 | 浏览器容器的登录态丢了。打开 noVNC 页面重新登录，下次读取会重新加载会话文件。 |
| 小红书报没有端点 | 到「浏览器」Tab 填共享端点，或在搜索卡片里填该后端自己的端点。 |
| 某家返回限流 | 那家拒绝了这次请求。等一会儿，或在它那一行调低每分钟上限。 |
| 提示「配置版本冲突」 | 另一个窗口先保存了。刷新页面后重新提交；草稿会保留。 |
| 保存被拒绝：浏览器端点不可达或令牌被拒 | 保存前的校验无法验证已启用的浏览器依赖。到「浏览器」Tab 点 **检查连接**，修好端点或令牌；或者先关闭所有浏览器相关功能离线保存。 |
| 校验问题提到的路由类型找不到 | 点问题后的修复链接：会切到对应 Tab、展开该路由的回退规则并聚焦控件。 |
