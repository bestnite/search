# dsh-search

[English](README.md) | 中文

面向 DeepSeek Harness 的多后端搜索插件，用 TypeScript / TSX 写成。兼容性以实际运行的版本为准，不绑定某个具体版本。

## 功能

- 21 个搜索后端，各自独立开关；支持的后端可以在**匿名**和**API Key** 两种接入模式里固定选一种
- 不自动切换后端、不换凭证、不改端点、不跨模式回退；失败就是失败
- HTTP 重试可配置且有上限，支持取消、总超时和 `Retry-After`
- 按接入模式标注费用档、额度说明（含核实日期）和官方来源
- 原生「设置 → 网页搜索」管理页，中英双语，公开配置项全部可改，含凭证管理、校验、诊断和显式试搜
- 支持并行搜索或单后端搜索，按 URL / 标题去重，RRF 或后端顺序融合
- 内存缓存有容量上限；**失败的请求永不进缓存**
- 本地尝试额度按「后端 + 模式」持久化，发送前原子预占、串行化。按 UTC 跨日重置；这是本地计数，不是服务商余额，也不代表账单上限
- 部分失败和全部失败都会写进 Agent 能看到的返回内容，不会伪装成「没有结果」

首次安装时**所有后端都是关闭的**。即使平台宣称有免费额度，账户类后端开启后仍可能产生费用。保存了 Key 也不会自动启用任何后端。供应商内部的路由、重试和融合由对方控制，不属于本插件的可配置范围。

## 开发

```sh
npm install --ignore-scripts --legacy-peer-deps
npm run check
```

DSH 的对等依赖（peer）需要从兼容的已安装运行时或兼容的开发环境解析。本机开发时用软链接指向已安装的 DSH 包，这些链接不属于可移植的构建依赖。客户端的 React 由 DSH 的模块加载器注入，不会被打包两份。TypeScript、esbuild、tsx 只用于开发；运行时只用平台自带的 Fetch API 与 Node crypto。配置、凭证、持久化存储以及用于记录校验的 zod 均由 DSH 提供。

## 安装与配置

可以从 npm 安装（`@nite07/dsh-search`）；改源码时先构建，再用 DSH 插件管理器安装本目录。打开「设置 → 网页搜索」，逐个选择后端的接入模式、核对价格、设置端点和参数，只启用你需要的后端。**改了配置要先保存**，再编辑凭证或执行试搜。凭证引用只是环境变量风格的标识符，密钥通过 DSH 凭证服务保存，不会出现在导出的配置里；删除已保存的凭证后，环境变量里的同名值可能重新生效。

插件注册的 provider id 是 `nite-search`，但它**不会**自动修改当前生效的搜索 / 抓取选择，也不会去禁用别的插件。迁移需要显式选中新 provider，同时保留原来的抓取 provider。旧的搜索插件建议保留为禁用状态，以便回滚。设置页会显示当前实际生效的 provider，不是本插件时提供一键切换。

腾讯云 WSA 用的是一条 JSON 凭证 `{"secretId":"...","secretKey":"..."}` 加官方 HTTPS 根地址，不是 Bearer 认证。

## 边界与证据

后端契约、价格与实测记录见 [docs/BACKENDS.md](docs/BACKENDS.md)，实施计划见 [docs/PLAN.md](docs/PLAN.md)，当前验证状态见 [docs/VERIFICATION.md](docs/VERIFICATION.md)。「文档核实」「模拟契约测试」「真实匿名调用」「付费账户验证」是四个不同层级的证据，不要混用。带 Key 的后端在没有凭证、没有明确费用授权的情况下不做在线验证。HTML 抓取和第三方 MCP 的响应格式可能变化；无法识别的响应会报协议错误，而不是假装「没有搜索结果」。

插件公开的配置项都能在表单里修改，但这不等于上游厂商暴露的每个参数都已实现；不支持的通用筛选参数会明确说明。域名包含 / 排除还会在本地再过滤一次。缓存、诊断和熔断状态是进程内状态；尝试额度跨配置重载保留。持久化的额度只针对单个 Host 进程，不跨多个 DSH 实例协调。

语言和地区使用固定的规范列表，因为各家写法并不统一（Brave 用 `zh-hans`、Serper 用 `zh-cn`、SearXNG 用 `zh-CN`、You.com 用大写主语言标签）。每个适配器自行转换，转不了就跳过并给出提示。
